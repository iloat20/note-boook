**结论**：P0/P1 性能瓶颈已在 7/20 批次解决，剩余均为 P2/P3 低收益项，纳入日常维护即可，不必单列迭代。

| 改进点 | 状态 | 说明 / 预期效果 |
|--------|------|----------------|
| 首页数据三份冗余 | ✅ 已解决 | 移出 `data`，setData 体积降 60%+，价格刷新更顺滑 |
| 滚动数字 50 次 setData | ✅ 已解决 | 移除 `animateAllValues`，切 tab 不再连打 50 帧 |
| `onShow` 无节流/过度 `force` | ✅ 已解决 | 30s 节流，切 tab 卡顿消除 |

| 隐藏 canvas | ✅ 已解决 | 按需挂载 |

**优先级建议**：性能方向当前 **P3 维护级**，不作为冲刺项。预期效果：首屏与切 tab 流畅度已达标。

## 二、用户体验提升（现状：基础好，缺引导与导入）

**优势（保留）**：iOS 磨砂玻璃设计、纯本地隐私安全、分层架构清晰。

**核心痛点（按可用性研究 + 当前代码核对，按优先级）**：

1. **P0 新手引导缺失**——无引导教程、无示例数据、空状态仅占位。
   - 建议：首启引导浮层 + 「载入示例数据」按钮（纯本地 seed，零风险）；可复用现有 `components/empty-state`。
   - 预期：新用户激活率提升，首屏不再"空"。
2. **P0 数据导入困难**——仅 JSON 备份/导入，不支持券商导出 / CSV / 剪贴板。
   - 建议：CSV 导入（`wx.chooseMessageFile` + 解析）、剪贴板粘贴导入。纯客户端可实现。
   - 预期：解决第二大痛点，显著降低录入门槛。
3. **P1 图表/可视化单一**——用户期望 K 线 / 走势 / 对比。
   - 注意：当前**刻意不用图表库**，且架构审查明确「不引入运行时图表库（ECharts）」以保持供应链干净。
   - 建议：优先级降低；若做，用 canvas/WXS 轻量自绘**用户自有数据**的走势，避免引入 ECharts。
4. **P1 价格提醒**——无目标价 / 涨跌幅提醒。详见第三节（受个人主体推送限制，建议「打开即检查」而非云端推送）。

## 三、功能扩展（现状：最大空白，本报告重点）

### 3.0 约束前提（决定每个功能的可行性）

- **纯客户端、无后端**：所有功能优先本地实现，不引入服务器。
- **微信个人主体合规（硬约束）**：曾因「个人主体不得经营股票类目」被拒，UI 文本已中性化为「资产 / 收益 / 其他收益」。
  > 🔴 **任何新功能的用户可见文案必须保持中性**，不得出现「股票 / 持仓 / 分红 / 证券 / A股 / 港股 / 美股」。内部逻辑（MARKETS 枚举、`utils/models/dividend.js`、按代码识别市场等）保留不变。新页面/新按钮的文本、分享卡片、订阅消息模板都需过一遍合规词表。
- **现有可扩展接缝**：`platform/`（网络/存储可整体替换，为未来后端留口）、分包懒加载、`models/services` 单向分层、`CACHE_TYPES` 枚举、`constants/market.js` 市场注册表。

### 3.1 高 ROI、契合约束（建议优先）

- **A. 新手引导 + 示例数据（P0）**
  - 形态：首启浮层引导 + 「载入示例数据」按钮，纯本地 seed。
  - 复用：`components/empty-state`；示例数据走现有 `Transaction.create/save` 写入本地。
  - 预期：新用户激活率↑，首屏不再空；零合规风险。
- **B. 多账户 / 组合管理（P0/P1）**
  - 形态：在 `Transaction` 模型加 `accountId` 维度（默认空=默认账户，向后兼容），`positionService` 按 `(accountId, stockId)` 聚合；新增账户切换 tab。
  - 契合纯客户端；不破坏现有接口。
  - 预期：多账户用户核心诉求，提升留存。
- **C. 资金流水（入金/出金）+ XIRR 真实年化（P1）**
  - 形态：新增 `cash_in` / `cash_out` 交易类型（本地），`annualReport` 接入 XIRR 计算真实年化收益率。
  - 契合纯客户端，补齐「年化收益率」分析空白。
  - 预期：分析深度显著增强，用户可看真实回报。
- **D. 数据导入（CSV / 剪贴板）（P0）**
  - 形态：`wx.chooseMessageFile` 选 CSV → 解析映射字段 → 批量 `persistTransaction`；剪贴板粘贴同理。
  - 预期：解决第二大体验痛点，录入门槛大幅下降。

### 3.2 中 ROI / 受约束

- **E. 价格提醒（打开即检查）（P1）**
  - 形态：本地记录目标价，`onShow` 检查并 banner 提示；如需推送用 `wx.requestSubscribeMessage`（用户主动订阅，个人主体可用）。
  - **避免**云端常驻推送（需后端，与纯客户端冲突）。
- **F. 目标价管理（P1）**：与 E 配对，存本地。

### 3.3 需后端 / 高合规风险（标注为未来，当前不建议）

- **G. 云同步（旧报告 P0，但需后端）**：与「纯客户端」定位冲突，个人主体做数据存储有合规与成本门槛。标记为**重大架构决策**，非当前阶段。
- **H. 社区 / 排行 / AI 分析（旧报告 P2）**：需后端 + 内容审核，个人主体高风险，暂缓。

## 六、落地建议（分阶段）

1. **第一阶段（1–2 周）**：A + D —— 体验与导入，纯客户端、零合规风险、见效最快。
