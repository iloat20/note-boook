# 茄子笔记本 · 功能增量头脑风暴报告

> 日期：2026-07-21
> 目标：盘点**每个页面**还能加什么功能、**整个项目**还能加哪些功能，并标注在当前「微信个人主体」约束下的可上线性。
> 约束背景：小程序曾因「个人主体不得经营股票类目」被拒。结论——**微信审核只看运行期用户可见内容（UI 文案/截图/类目），不查源码变量名**。因此改造策略是「剥离用户可见的股票/持仓/分红/证券/A股/港股/美股 等词，内部逻辑保留」。本报告所有 UI 文案一律沿用「资产 / 记录 / 转入 / 转出 / 其他收益」中性措辞。

---

## 可行性图例

| 标记 | 含义 |
|------|------|
| 🟢 | **可上线** — 纯客户端、不触发股票类目、UI 中性，想到就能做 |
| 🟡 | **需改造** — 功能有价值，但需把行情/个股相关措辞中性化、避免类目嫌疑，或交互上规避「荐股/实时行情服务」观感 |
| 🔴 | **需企业主体或后端** — 云同步、订阅消息推送、外部金融数据抓取/券商导入等，个人主体无法合规上线 |

> 注：仓库已**无 ECharts、无分红独立页、无多市场 tab**（2026-07-20 架构审查已对齐代码事实）。所有图表须用 **CSS / `<canvas>`**（唯一 canvas 是首页分享卡与年度报告）。分红在 UI 以「其他收益」呈现。本报告基于**当前真实代码**梳理，而非早期那份已部分失真的《可用性研究报告》。

## 一、按页面盘点

### 1. 首页 `pages/index`（资产列表）
**现状**：持仓卡片、左滑三操作（编辑 / 转出 / 删除）、单卡实时价值刷新（↻）、分享卡片、滚动分页、FAB（+ 点击快捷记账 / 长按跳完整记账）、空状态。

| 功能 | 可行性 | 说明 |
|------|--------|------|
| 下拉刷新全部价值 | 🟢 | 复用现有单卡 `onRefreshPrice`，加页面级 `onPullDownRefresh` 批量刷新 |
| 排序 / 分组（按变动幅度、按名称、按最近变动） | 🟢 | 纯前端，复用 `positionCalculator` 输出 |
| 资产占比迷你条（持仓价值占总额百分比） | 🟢 | CSS 进度条，无需图表库 |
| 置顶 / 拖拽排序常用资产 | 🟢 | 本地顺序存 `storageCore` |
| 单资产快捷备注 / 标签 | 🟢 | 复用 `strategy-tags` 体系 |
| 长期未变动资产「休眠」标记 | 🟢 | 依 `lastUpdated` 计算 |
| 一键刷新全部（替代逐卡点） | 🟢 | 批量调 `fetchAllPrices` |
| 资产搜索直达历史/详情 | 🟢 | 复用 `searchHistory` 机制 |
| 「示例数据」一键填充（新用户引导） | 🟢 | 见项目级 § 二.7 |
| 实时行情自动轮询 | 🟡 | 个人主体下「持续推送行情」观感有风险，建议仅手动刷新 + 进入页面时拉一次 |

### 2. 历史 `pages/history`（记录列表）
**现状**：搜索 + 搜索历史、分段筛选（全部 / 转入 / 转出）、策略 chips 筛选、批量选择删除、分页、长按操作、空状态。

| 功能 | 可行性 | 说明 |
|------|--------|------|
| 日期范围筛选（自定义起止） | 🟢 | 复用 `utils/helpers/dateRange.js` |
| 按资产分组 / 折叠 | 🟢 | 现有 `groupedHistory` 按日，扩展为按资产 |
| 当期小计（筛选结果合计金额） | 🟢 | 纯前端聚合 |
| 撤销删除（误删恢复） | 🟢 | 删除前入临时回收栈 |
| 批量打标签 / 批量改备注 | 🟢 | 复用 `batchSelect` + `strategy-tags` |
| 按金额 / 时间排序切换 | 🟢 | 复用 `sortHelpers` |
| 导出当前筛选结果为 CSV / Markdown | 🟢 | 复用 stats 的 `onExportMD` 思路 |
| 日历视图（按日聚合热力） | 🟡 | 中性「记录密度」，规避行情热力图观感 |
| 关联交易合并展示（一笔转入拆多笔） | 🟢 | 数据层已支持 |

### 3. 统计 `pages/stats`（汇总 + 年报入口）
**现状**：4 张双列卡片（资产变动 / 记录次数 / 期末资产 / 记录天数）、完整明细、已结束资产、年度报告 CTA、导出 MD、清除数据。

| 功能 | 可行性 | 说明 |
|------|--------|------|
| 周期切换（周 / 月 / 年） | 🟢 | 复用 `statsService` 已有聚合维度 |
| 月度 / 年度走势（CSS 柱状或 canvas 折线） | 🟢 | 用 canvas 画轻量走势，不引入图表库 |
| 分类维度汇总（按标签聚合净变动） | 🟢 | 复用 `strategy-tags` 元数据 |
| 关键比率（持有期回报、周转次数） | 🟢 | 纯计算，措辞中性 |
| 多格式导出（图片长图 / PDF 截图） | 🟢 | 复用分享卡 canvas 思路 |
| 对比「本期 vs 上期」 | 🟢 | 前端差值计算 |
| 收益率曲线 / 回测 | 🟡 | 个人主体下「收益率展示」需中性化为「资产变动率」，勿出现荐股语境 |

### 4. 详情 `packageDetail/pages/detail`（单资产）
**现状**：Hero（名称 / 代码 / 总变动）、持有摘要、变动明细、交易记录分组折叠（含日记 + 策略标签）、笔记复盘（策略汇总）、编辑抽屉（数量 / 成本 / 当前价）。

| 功能 | 可行性 | 说明 |
|------|--------|------|
| 单资产分享卡片 | 🟢 | 复用首页分享卡渲染 |
| 持有占比（该资产占总资产 %） | 🟢 | CSS 占比条 |
| 编辑增强：改备注 / 加标签到「持有」本身 | 🟢 | 数据模型已支持 `Transaction` 字段 |
| 删除资产二次确认 + 结清处理 | 🟢 | 复用 `markDataDirty` |
| 历史价值走势（手动记录点连线） | 🟢 | 用每次记录的成本/价值做散点折线，canvas |
| 相关记录快捷筛选（同标签其他资产） | 🟢 | 复用 `pinyinIndex` / 标签索引 |
| 外部行情页跳转 | 🟡 | 个人主体下不要做「点开看实时行情大图」式交互，保持纯记账视角 |
| 分红 / 其他收益独立时间线 | 🟢 | 已以「其他收益」呈现，可单独成时间线 |

### 5. 记账 `packageRecord/pages/record`（完整录入）
**现状**：代码智能识别 + 联想 + 搜索历史、转入 / 转出、单价 / 数量 / 日期 / 时间 / 备注、策略标签 + 自定义、实时预览金额、编辑模式。

| 功能 | 可行性 | 说明 |
|------|--------|------|
| 金额反算数量（输入总价自动除单价） | 🟢 | 简单计算 |
| 草稿暂存（误关不丢） | 🟢 | 本地草稿 key |
| 重复 / 模板记账（复用上次） | 🟢 | 读最近一条 |
| 批量录入（多笔同资产） | 🟢 | 循环写 `Transaction` |
| 拍照 / 截图识别单据 | 🔴 | 需 OCR 后端或云函数，个人主体难合规 |
| 费用 / 税费字段回填 | 🟡 | 之前 `feeCalculator` 已删除；如需「费用」概念，建议中性化为「其他费用」并纯本地计算，不接券商费率表 |
| 关联交易（一笔转出对应一笔转入） | 🟢 | 数据层已支持 |

### 6. 快捷记账 `components/quick-record`
**现状**：简化录入、数量预设（100 / 500 / 1000 / 全部）、日期折叠、预览。

| 功能 | 可行性 | 说明 |
|------|--------|------|
| 最近使用资产快捷选择 | 🟢 | 读 `searchHistory` |
| 默认日期 = 今天、可一键「刚才」 | 🟢 | 时间预设 |
| 金额快捷档位（如 1k / 5k / 1w） | 🟢 | 同数量预设思路 |
| 默认标签记忆 | 🟢 | 上次所选标签 |
| 长按 FAB 直接唤起带预填的快捷记账 | 🟢 | 已有长按跳 record，可改为预填 |

### 7. 年度报告 `components/annual-report`
**现状**：年度总览（流入 / 流出 / 净变化 / 期末）、持有画像（在册最久 / 最短 / 变动最多）、分享生成中。

| 功能 | 可行性 | 说明 |
|------|--------|------|
| 月度趋势条（12 月流入流出） | 🟢 | CSS 柱状 |
| 分类维度复盘（按标签年度净变动） | 🟢 | 复用标签元数据 |
| 多年对比（选年切换） | 🟢 | `annualReport.js` 已按年聚合 |
| 更多画像指标（最长连续记录、平均持有期） | 🟢 | 纯计算 |
| 导出为图片长图 | 🟢 | 复用 canvas |
| 分享到会话 / 生成海报 | 🟡 | 分享卡片文案须中性，避免出现「收益」「年化」等敏感词，用「资产变动」表述 |

### 8. 公共组件
- `strategy-tags`：🟢 支持标签颜色自定义、标签搜索过滤。
- `liquid-slider`：🟢 现有分段控件，可扩展为多段（按标签）。
- `empty-state`：🟢 支持不同 icon / 引导按钮（如空态直接「去记一笔」）。

## 二、项目级功能（跨页面）

| 功能 | 可行性 | 说明 / 中性措辞 |
|------|--------|----------------|
| **多账本 / 组合** | 🟢 | 中性「账本 A / 账本 B」，本地切换，统计独立。纯客户端可做 |
| **数据导入（CSV / 券商导出文件）** | 🟡 | 纯本地解析 CSV 可上线；但若提供「券商一键导入」涉及外部金融数据，需企业主体 |
| **数据导出增强（JSON 备份已有 → 加 CSV / 图片）** | 🟢 | 复用现有备份机制 |
| **资金流水 + 内部收益率（XIRR）** | 🟢 | 中性「资产变动率」，纯计算，`xirr` 逻辑历史上存在过 |
| **新用户引导 + 示例数据** | 🟢 | 首次进入弹引导，一键填示例，降低空态门槛 |
| **深色模式** | 🟢 | 跟随系统或手动切换，纯 WXSS 变量 |
| **隐私锁（面容 / 手势密码）** | 🟢 | 本地校验，不联网 |
| **多币种（已有 `exchangeRate` 服务）** | 🟡 | 接入 UI 选币种 + 汇率换算；汇率源需谨慎，建议内置静态或手动填写，避免实时外部金融数据 |
| **价格提醒（目标价 / 涨跌幅推送）** | 🔴 | 需订阅消息 + 后端轮询，且「行情提醒」易触发类目审查，个人主体不建议 |
| **云同步 / 多设备** | 🔴 | 需微信云开发（企业主体更易过审），个人主体难合规 |
| **AI 洞察（自然语言复盘）** | 🔴 | 需后端 API Key / 云函数，个人主体不建议内置 |
| **社区 / 排行分享** | 🔴 | 涉及 UGC 与金融讨论，企业主体 + 内容安全才可行 |
| **图表增强（走势 / 对比，无 ECharts）** | 🟢 | 用 canvas 或纯 CSS 实现，保持记账视角，不引入「行情软件」观感 |

## 四、与既有文档的关系

- 本报告**取代**早期《可用性研究报告.md》的功能清单——该报告声称「ECharts 图表 / 分红管理页 / 多市场标签页 / 实时股价获取」等，已与 2026-07-20 架构审查代码事实不符（ECharts 与分红页已移除、市场 tab 已改为自判选中、外部行情仅腾讯财经 `qt.gtimg.cn`）。
- 功能落地前，请以 `docs/architecture-review-2026-07-20.md` 与 `AGENTS.md` 的当前架构事实为准。
- 所有 🔴 项在当前个人主体下**不应排期**，待主体升级或后端就绪再评估；🟡 项可在「中性措辞 + 纯客户端」前提下做。
